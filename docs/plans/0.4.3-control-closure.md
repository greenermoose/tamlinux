# 0.4.3 retained network/power controls and plugin setters

**Status:** Implemented and verified in Develop, 2026-10-12. Nineteen retained
controls and one shared preservation helper are packaged. This follows
[retained audio closure](0.4.3-audio-output-closure.md). No candidate pin, letter,
installation or lifecycle stage changed.

## Behavior and providers

The network/status/band/password/QR/speedtest chain and Wi-Fi restart retain
their panel/menu interfaces. Band selection preserves the previous profile
setting and restores it if reassociation fails. QR generation escapes SSID and
secret data, supports open/WPA/WEP and rejects enterprise authentication.
Secrets are emitted only when the user invokes password/QR sharing. Speed tests
retain the explicit Fast.com workflow; verification does not contact it.

Bluetooth power uses rfkill's persistent soft block; the native systemd-rfkill
service owns its persistence. Device actions retain their bounded, best-effort
pair/trust/connect/disconnect/remove behavior: exit zero is not proof of an
accepted BlueZ operation. Bluetooth restart retains its existing unblock/list
behavior; it does not restart the daemon despite the historical command name.

Power profiles retain per-source ac/battery preferences, automatic source
selection and the offered-profile list. An unavailable profile service now
returns an explicit failure without saving a preference. A failed set retains
the existing preference. UPower/sysfs battery telemetry and system statistics
remain read-only. Automatic source detection retains its existing AC fallback
when the UPower query is unavailable; native service proof must cover this limit.

Stay Awake, night light and hyprsunset restart are packaged. The shell and idle
helper now agree on `$XDG_STATE_HOME/tamlinux/stay-awake` (standard HOME fallback)
and `TAMLINUX_STAY_AWAKE_FILE`. The shell setter invokes the same preserving
helper instead of its own touch/remove writer. Native suspend integration must
use the same selection; screensaver/lock/suspend chains are still pending.

`tam-display-text-size` follows XDG state/config roots, changing shell base size,
GTK scale and the four retained terminal configurations together. GNOME schemas
and the dconf client/backend are delivered explicitly. It verifies the GTK set
before changing files because a failed asynchronous dconf commit can exit zero.
It rejects existing non-writable files before mutation; running terminal reloads
and the Foot restart notification retain their prior behavior.

`tam-weather-location` writes the same XDG JSON consumed by weather and tides,
validates coordinates and preserves the previous file on set/clear. Its existing
IP-location fallback is an explicit external-provider boundary. Tides' dedicated
location setter and monitor layout/settings writers are already embedded in the
plugin output; their complete migration/recovery proof remains pending.

Delivery wraps declared client tools and same-output sibling helpers. Native
NetworkManager, systemd-resolved, BlueZ, systemd-rfkill, UPower, optional
power-profiles-daemon, Hyprland/hyprsunset, UWSM, device ACLs and authorization
still belong to the independently supplied host. Installing clients enables no
service and establishes no live-service/hardware proof.

## Paired mutable state and recovery

| Interface | Reader/writer and state | Preservation/recovery boundary |
| --- | --- | --- |
| DNS global files | Native NetworkManager reads `/etc/NetworkManager/conf.d/20-tamlinux-dns.conf`; resolved reads `/etc/systemd/resolved.conf`; `tam-dns` writes both. | Root-private snapshot of bytes, symlink identities or explicit absence before either file changes. Existing whole-file resolver replacement is retained. |
| DNS connection fields | NetworkManager persists each wireless/Ethernet profile's `ipv4/ipv6.dns` and `ignore-auto-dns`; setter updates the captured profile list. VPN profiles stay out of this operation. | Capture all four fields for every affected UUID before any file/profile mutation. List/query/backup failure aborts. Capture service active-state observations; live reapply/reload remains best effort. |
| Wi-Fi band | NetworkManager profile `802-11-wireless.band` read/written by band helper. | Preserve profile and previous value before setting. Failed reassociation restores the previous value and attempts reconnection. |
| Bluetooth | BlueZ adapter/pairing state and `/var/lib/systemd/rfkill` native soft-block persistence. | Native state owner; no direct file edits by these commands. Pair/remove and radio recovery require host/physical proof and later migration collection. |
| Power preference | Helper reads/writes `$XDG_STATE_HOME/tamlinux/powerprofiles/{ac,battery}`; native daemon owns active profile. | Explicit selections preserve preference/absence and active-profile/source observations; successful daemon set precedes atomic preference write. Automatic restore writes no preference. |
| Stay Awake | Shell reader/setter and CLI share `$XDG_STATE_HOME/tamlinux/stay-awake` or explicit override. | Preserve marker/absence before touch/remove, including shell IPC changes. Earlier indicators-path state requires offline migration classification. |
| Text size | Theme payload reads `$XDG_STATE_HOME/tamlinux/shell.toml`; terminal readers use `$XDG_CONFIG_HOME/{alacritty/alacritty.toml,kitty/kitty.conf,ghostty/config,foot/foot.ini}`. GTK reads its dconf scale key. | Preserve all five file states plus effective GTK factor and the explicit user value (empty means no override). Verify GTK before paired writes. Later file errors may leave a partial change with originals retained. |
| Shared weather location | Weather and tides read `$XDG_STATE_HOME/tamlinux/settings/weather.json`; CLI writes/removes it. | Preserve old bytes/absence, validate first, atomic set; no automatic pruning. |
| Night light | Hyprland/hyprsunset live temperature and process state. | Native process/IPC boundary; status does not launch a daemon. No persistent config is written here. |

User snapshots are mode-0700 directories under
`$XDG_STATE_HOME/tamlinux/settings-recovery/<kind>.*`. The helper prints their
path only after writing a complete `manifest.json`. Each entry records its
original destination, absence or saved bytes and any symlink target. Incomplete
snapshots are retained on failure but never permit the caller to mutate state.

DNS uses `/var/lib/tamlinux/network-recovery/dns.*`, mode 0700, with
`manifest.tsv`, numbered original/content files or `.absent` markers, affected
UUIDs and per-field observations. Privileged writes use fixed destinations and
`/usr/bin:/bin`, honor no path override, and run only the immutable Nix-store
body through native `/usr/bin/pkexec`. Unprivileged reads retain fixture overrides.
No privileged command ran during development verification.

Recovery is explicit: preserve current files and later user writes first;
review the manifest; restore only selected original bytes/link identities or
remove an originally absent destination only if still owned by this attempt.
Restore or reset the GTK user key according to its saved explicit value. Restore
only selected NetworkManager profile fields through native nmcli, then reapply
and reload the corresponding services. Restore power/band selections only when
still supported. Service-query failures and saved effective values alone are
not authority to recreate earlier enablement or defaults. No automatic rollback
or snapshot pruning runs here; offline migration and real recovery proof remain
required for the independence gate.

## Verification and continuation

new control tests. Eighteen service checks and 21 auditor regressions pass. Five
preservation-failure cases reject the original implementations for text size,
idle/weather, power selection, Wi-Fi band and DNS. Root DNS tests instrument only
a disposable body to substitute fixed paths/authorization; this is recorded
logic evidence, not a privileged execution test.

schema/backend and unavailable service cases are exercised with caller tools
excluded from PATH and both bus addresses unavailable. DNS/package checks never
authorize a write, reset radios, pair devices or launch a real desktop.
