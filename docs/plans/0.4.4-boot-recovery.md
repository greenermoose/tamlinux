# 0.4.4 boot ownership and recovery

Candidate e prepares the next boot handoff while retaining d's desktop/login
implementation. The matching package assembly selects exact native provider
archives and records their build inputs. Machine settings remain consumer
configuration; they are not installed as vendor defaults for every machine.

Use the upstream-author AUR recipes for `limine-mkinitcpio-hook` and
`limine-snapper-sync`. Review the recipe, source, final archive and transaction
hooks before selecting an archive. Freeze source inputs first; select the
archive hashes after isolated replacement, generation and recovery rehearsals,
and before preparing the e assembly. Installation is a later Test operation.

Preserve the effective initramfs architecture, UKI paths, root/resume arguments,
snapshot policy and boot-menu structure. Keep storage identifiers unchanged.
Use stock Plymouth `bgrt` and a `Tamlinux` direct menu label. A consumer that
already has a generated Recovery folder preserves it rather than changing the
generator's target name indiscriminately.

The AUR kernel recipe overlays its mkinitcpio-specific files after the generic
entry-tool files. The final EFI hook therefore invokes `limine-install` with
registration enabled. Review the final archive, not just the generic source
file. Consumer policy may override the hook to pass `--no-efi-register` while
maintaining the existing registered and fallback EFI files.

Replacing the provider also replaces initcpio hook files, which can trigger
image generation during pacman installation. A reviewed transaction can use a
separate final `--hookdir` containing explicit `/dev/null` masks, retaining the
normal consumer hook directory first. A mask at a package-owned path can be
overwritten during extraction. Verify suppression using before/after hashes,
then verify that the normal update path remains enabled.

Before host changes, retain exact old native archives and package reasons,
effective configuration, generated images, snapshot manifests/cache/history,
both EFI destinations, firmware state and an independent rescue route. Preserve
later writes separately before restoration. Provider and file restoration is
not equivalent to selecting an older Home Manager generation.

The first physical Test covers normal Linux boot/unlock/login, regeneration
followed by boot, Windows and the concrete fallback/recovery routes. Isolated
generation and file restoration are development evidence; they do not establish
physical boot acceptance. Menu visibility is diagnosed before requesting a
selection the user cannot see. Sleep/resume and the carried installation and
later-write recovery cases still precede the pre-removal Run. Old core packages
remain installed until a subsequent removal candidate.
