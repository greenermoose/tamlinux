## Key decisions and implementation notes

- The next step in the private plan was the command menu, the seventh shell
  function to move into the host. The menu, its tree and search model, and
  the desktop-application library behind its Apps list are vendored from the
  Omarchy 4.0.4 shell with the MIT notice, together with the hidden-entry
  scan and the application search helpers. The model and search helpers are
  unchanged. The IPC target is `menu` (`toggle`, `summon`, `open`, `close`,
  `refresh`, `ping`); the layer is `tamlinux-menu`.
- Behavior is kept: the JSONC tree with dotted ids, aliases, `when` and
  `checked` guards evaluated in one batched shell, search across the
  subtree, the Apps list with icons and launch feedback, the uninstall
  confirmation, and the select/input mode that answers a waiting command
  through a selection file and a done file.
- The two menu files are named by `TAMLINUX_MENU_DEFAULT` and
  `TAMLINUX_MENU_EXTENSION`, defaulting to `~/.config/tamlinux/menu/`. The
  host does not ship a tree; the workstation configuration supplies one.
- Each action runs in its own transient systemd scope. The services unit is
  a systemd service, so anything the menu started as a plain child would
  be stopped when the unit restarts.
- The application library belongs to the menu and loads the first time the
  Apps list or a search needs it, so a menu that is only used for actions
  never scans the icon directories. Launch feedback goes to the host's OSD
  service when it runs. Removal runs the command named by
  `TAMLINUX_APP_REMOVER`; without one, Delete does nothing. The configured
  hides file is `TAMLINUX_MENU_HIDES`, and it is reread when it changes.
- Select/input answers are written by a fixed `sh -c` script with the
  answer and paths as arguments, as in the image picker. Provider actions
  quote their value with a local helper. The confirmation dialog and pointer
  gate are the clipboard picker's components.

## Verification

- `python3 -m unittest discover -s desktop/tests`: 60 tests pass.
- A copy of the host ran in a headless nested Sway session with
  `TAMLINUX_BAR=0 TAMLINUX_SERVICES=osd,menu`, the workstation's menu files,
  and recording stubs for `systemd-run`, `uwsm-app`, and the remover.
  Through IPC and synthetic keys: the root, System, and Quick Launch menus
  opened with their guards applied; typing filtered the tree; Down and Enter
  ran the selected action inside the scope command; an alias that names an
  action ran it directly; Left returned to the parent; `toggle` closed an
  open menu and Escape closed it. The Apps list loaded with icons, Enter
  launched an application through `uwsm-app` and `gtk-launch`, and Delete
  showed the confirmation, where Cancel did nothing and Uninstall ran the
  remover with the id and name. A select request with an option containing
  `$(touch PWNED)` and a tab-separated subtext, and an input request typed
  as `x;$(touch PWNED)`, both returned the text unchanged in the selection
  file and nothing ran; Escape on an input request created only the done
  file. Screenshots matched the source layout.
- The scope command ran against the live user manager and placed the
  process in its own scope under `app-graphical.slice`.
