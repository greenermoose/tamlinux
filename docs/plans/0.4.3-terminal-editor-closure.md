# 0.4.3 implementation order and terminal/editor slice

**Status:** Implemented and verified in Develop, 2026-10-10. No candidate prepared
or installed.

The accepted desktop depends on helpers that are absent from its package outputs.
Complete those interfaces before producing session defaults or an assembly that
would only work with a developer's personal PATH. The scope and acceptance remain
those in [the independent installation plan](non-theme-compatibility.md).

## Priority order

1. **Review menu/keybinding scope before more ports.** Classify baseline callers
   as retained, optional with an independent provider, or proposed for retirement.
   Record specific rows, other callers and feature disposition before implementing
   their closure. Menu-only does not mean unused. Previously retained functions
   require an explicit scope amendment before deletion; missing package commands
   do not authorize it. Add compact read-only reporting to the existing delivery
   auditor while retaining its complete evidence and blocked-readiness exit status.
2. **Complete runtime helper chains.** Start with terminal/editor launching and
   defaults because config editing, plugin terminal actions and menu maintenance
   share them. Then transfer browser/agent defaults, controls and plugin setters,
   theme/background/fonts and capture/recording/OCR/QR chains. Inspect each audit
   finding against an actual baseline caller; package transitive dependencies
   with the caller. Record owned paths and required/optional application choices.
3. **Deliver session and host ownership.** Package fresh-login Hyprland defaults,
   keybindings, environment, desktop entries, browser registrations, editor
   defaults and required native services/hooks. Inspect effective settings and
   boot/update ownership before transferring it. The completed helper interfaces
   determine configuration and native dependencies, avoiding a second cutover.
4. **Implement migration and recovery.** Populate the mutable-path manifest from
   settled readers/writers. Preserve selections and originals, reject conflicts,
   support interruption/retry and preserve writes made after conversion on rollback.
5. **Build and prove a complete assembly.** Pin independent providers, prepare
   a reusable clean Arch image/consumer recipe, build outputs and run installation,
   login, fixed workflows and attempted-network observation. Implement the finite
   I01–I09 aggregation while collecting evidence; missing cases stay pending.
6. **Prepare reference-machine Test.** Allocate an unused candidate letter only
   for the selected exact artifacts, record native/boot/mutable recovery and the
   inspected removal transaction. Test, Run and Release are explicit transitions.

Each chain is developed and verified as a complete installed interface before
moving to the next. Static audit counts measure remaining review work, not desktop
acceptance. Capture geometry redesign and Tamarack visual changes remain deferred.

Plan focused input improvements as **0.4.4**, after independent 0.4.3 acceptance
and before the visual redesign. Review the exact map and preserved workflow
coverage; a 38-binding target is a proposal, not an automatic deletion criterion.
Prioritize the confirmed close/launch chord conflict, terminal selection/paste,
TUI mouse overrides and accessible close controls. Do not intercept application
Escape or replace browser/editor context menus with a global paste binding.

## Implement now: terminal/editor chain

Transfer these nine commands into maintained product source with Makefile install
interfaces and original license notices:

- `tam-launch-terminal` and `tam-cmd-terminal-cwd`: launch in the focused terminal's
  directory, with a home-directory fallback and an owned Kitty socket name.
- `tam-launch-editor` and `tam-launch-config-editor`: use the selected editor,
  preserve inline/terminal/graphical routing and notification behavior.
- `tam-launch-floating-terminal-with-presentation`, `tam-show-logo` and
  `tam-show-done`: retain presentation windows, theme styling and completion pause,
  using owned theme state and preserving command arguments.
- `tam-default-editor` and `tam-default-terminal`: supply menu readers/writers,
  preserve the editor state location, and honor XDG config for terminal preferences.

Delivery wraps implementation tools and resolves sibling commands from the same
output. UWSM, xdg-terminal-exec, Hyprland and selected terminal/editor applications
remain declared host/application providers. The Kitty socket producer must be
retargeted in the later packaged terminal defaults; no old-name runtime fallback.

## Verification and limits

Install commands into a temporary prefix and test with empty home/XDG directories
and a restricted PATH. Record IPC, notification and terminal boundaries rather
than starting applications. Cover config editing, inline/graphical/TUI routing,
spaces/quotes/options in arguments, default selection, rejected selections, focused
terminal directory and fallback, owned presentation theme and completion behavior.
Run the real Nix output with only recorded host facilities on PATH, then repeat
the package-output audit. Package checks establish command closure, not physical
terminal rendering, clean graphical login, migration or 0.4.3 acceptance.
