# 0.4.3 retained audio output and tuning closure

**Status:** Implemented and verified in Develop, 2026-10-12. Nine owned commands
and the retained tuning payload are packaged. No source pin, candidate letter,
activation or stage promotion changed. This follows
[agent/microphone closure](0.4.3-agent-default-closure.md).

## Behavior and providers

`tam-audio-output-set-default` sets the PipeWire/Pulse default and moves only
application playback streams. DSP streams without application names and
EasyEffects output stay in place. Routing keeps its accepted best-effort behavior:
exit zero alone does not prove the server accepted the request.

`tam-audio-output-sink` resolves the selected default or explicit sink through a
speaker tuning or EasyEffects output stream. Physical headphones/HDMI remain the
selected volume target; idle/unlinked DSP sinks fall back to themselves.
`tam-audio-sink-availability` and `tam-audio-output-switch` exclude the physical
speakers while a matched tuning fronts them, preserving other device availability.
Switching retains mute state; `tam-audio-output-volume` changes physical loudness,
clamps it to 0–100%, and retains runtime mute debounce. `tam-osd` passes JSON to
owned shell IPC without interpreting message text as shell code.

`tam-audio-tuning`, `tam-hw-match` and `tam-restart-audio` retain matching,
optional speaker tuning and USB recovery. Shipped profiles are trusted code/data;
`TAMLINUX_AUDIO_DATA` remains an explicit override. The default now reads the
immutable command output's `share/tamlinux/audio`, including its license, dedicated
PipeWire client config, service and Dell profile. The profile's original hardware
validation claims are historical provenance, not new validation in this work.

Delivery wraps coreutils, Pulse/WirePlumber clients, awk, grep, sed, diffutils,
procps, systemd and jq as appropriate; sibling helpers resolve from the same
commands output. The native host supplies PipeWire's daemon/modules, user services,
DMI/sysfs/procfs and optional `lsp-plugins-lv2`. Tuning checks the native limiter
before writing. USB recovery checks native `/usr/bin/usbreset` and
`/usr/bin/pkexec`; Nix does not supply the privileged authorization endpoint.
Installing the command output enables neither audio services nor tuning.

## Paired state and recovery inventory

| Interface | Reader/writer and state | Recovery boundary |
| --- | --- | --- |
| Default output, streams, volume/mute | Routing/resolver/volume/switch/panel use PipeWire/Pulse server state. WirePlumber may persist defaults/routes. | Native service/state ownership; actual graph recovery requires host proof. |
| Mute debounce | Volume reads/writes `$XDG_RUNTIME_DIR/tam-audio-output-volume-mute-toggle.last`, falling back to `/tmp`. | Ephemeral marker, independent of persisted mute state; preserve accepted behavior. |
| Tuning host | Tuning writes/removes `$XDG_CONFIG_HOME/pipewire/tamlinux-speaker-tuning.conf`; PipeWire client reads it. | Snapshot before every nontrivial on/off mutation. |
| Tuning graph | Tuning renders `pipewire/tamlinux-speaker-tuning.conf.d/90-tuning.conf`; client reads it. | Same snapshot, absent files recorded explicitly. |
| Tuning unit | Tuning writes/removes `systemd/user/tamlinux-speaker-tuning.service`; systemd reads/enables/restarts it. | Snapshot records file plus queried active/enabled state and default sink. |
| Earlier owned drop-ins | Tuning removes `90-tamlinux-speaker-tuning.conf` in `pipewire/pipewire.conf.d`, `wireplumber/wireplumber.conf.d` and `pipewire/filter-chain.conf.d`; daemon-loaded removal calls restart. | All three included in the same snapshot; unrelated filters remain untouched. |
| USB default cleanup | Restart selectively removes USB sink defaults and USB route rows in `$XDG_STATE_HOME/wireplumber/default-nodes` and `default-routes`. WirePlumber owns their live persistence. | Both files copied to unique adjacent `.bak.*` files before either edit; any backup failure aborts automatic USB recovery. |
| USB device reset | Restart inspects sound-card/sysfs and blocked audio processes, then explicitly authorizes native usbreset when recovery detects a stuck device. | Physical reset cannot be undone by restoring files; never executed during development checks. |

Unset XDG roots use the standard HOME fallbacks. Tuning snapshots live under
`$XDG_STATE_HOME/tamlinux/audio-recovery/tuning.*`. `manifest.tsv` records six
original destinations, numbered preserved files or `.absent` markers; queried
service states and default sink are separate files. Backup failure stops before
file/service mutation. Installation failure stops with the snapshot retained;
a graph/link failure removes the attempted service/config and retains the
snapshot. Snapshots are not automatically pruned.

Recovery is explicit: preserve current files/new writes first; stop the owned
client; review the snapshot manifest and restore only the selected original
files (or remove only an originally absent file that still belongs to this
attempt); reload systemd, restore recorded service state and default sink where
still available. Do not overwrite later user writes or treat an unavailable
service query as proof of the previous state. A complete automated migration/
rollback collector and real-service recovery tests remain required for I05/I09.

## Legacy cutover inventory

Normal packaged audio uses only `tamlinux-speaker-tuning.conf`,
`tamlinux-speaker-tuning.service` and `tamlinux_speaker_tuning`/`_output` graph
identities. The panel and payload use the same owned prefix. There is no legacy
alias, fallback or automatic deletion of inherited files.

Before an in-place candidate is activated, offline migration must inventory and
preserve the prior tuning asset directory, inherited host config/fragment/unit,
three inherited drop-ins, enablement links, server selection and WirePlumber
state. Convert graph/service/config references together, with absent-destination
checks, validation and idempotence. Preserve custom assets using an explicit owned
override. Stop the prior service before starting the owned client to avoid duplicate
processing. Retained prior packages and unchanged originals implement rollback;
new user writes need their own preservation. Fresh-host installation needs no
legacy conversion. None of these migration steps ran on the workstation.
