**Status:** Implemented and verified in Develop, 2026-10-12. No candidate pin,

## Owned interfaces and tool edges

`tam-default-agent` now has maintained source, an MIT license and check/install
interface. Its writer and `tam-agent` reader use the same
`${XDG_CONFIG_HOME:-$HOME/.config}/tamlinux/defaults/agent` file. Unset state stays
unset. Aliases select canonical supported names, including availability checks.
Existing user-installed executables/symlinks are preserved; retained Mise package
routes still use the presentation terminal when installation is needed.
Installation failure preserves the selection. Successful writes use a temporary
file in the destination directory and atomic replacement.

The setter's complete command edges are `tam-agent`, `tam-cmd-present` and
`tam-launch-floating-terminal-with-presentation`; the presentation and agent
launchers reuse the existing owned terminal/IPC chain. Delivery supplies
coreutils, GNU grep and Mise, resolving helpers from the same commands output.
Selected applications, their credentials, the user/Mise application PATH,
UWSM and terminal facilities remain declared independent provider boundaries.
Only an explicit retained-agent selection can invoke its install route.

OpenClaw and Hermes support are retired on explicit owner direction. The setter
rejects their selection/install/availability requests before checking executables
or invoking any installer. `tam-agent` has neither launch route; the default menu
has neither choice. Existing selections, independently installed applications and
data are preserved. A stale selection fails without choosing a replacement.
Unbuilt Hermes bootstrap stubs are tested as rejected inputs and never executed.

`tam-audio-input-set-default` is the first controls chain: the audio panel passes
a node ID and source name; the helper sets the PipeWire/Pulse default and moves
existing capture streams. Delivery supplies `wpctl` (WirePlumber), `pactl`
(PulseAudio) and GNU awk. The existing best-effort failure behavior is preserved;
exit zero alone is not confirmation of successful audio routing. This helper
does not write configuration files directly; server-owned default/stream state,
including any WirePlumber persistence, remains part of native ownership/recovery.
No audio services are activated by installing these client tools.
