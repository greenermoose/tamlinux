# Start Fault G trial H1

**Status:** Approved; implementation complete in Develop, 2026-10-17.
The matching assembly records package readiness. Test activation and physical
proof are pending.
**Goal:** Deliver the hibernate-time zram drain through an exact Tamlinux package candidate, prove sleep/resume, and begin the H1 reliability trial.

## Starting point and recommendation

The developed hook is in `desktop/native/deferred/tamlinux-hibernate-swap`, outside the installed defaults tree. Candidate 0.4.4-e therefore does not deliver it. Existing regression tests exercise the script with simulated swap devices; they do not establish real sleep behavior or drain duration.

Prepare a new 0.4.4 candidate, **0.4.4-f**. Deliver the hook as
`/usr/lib/systemd/system-sleep/tam-hibernate-swap`, following the executable naming rule. Keep the existing journal tag `tamlinux-hibernate-swap`, runtime state namespace and `TAMLINUX_*` variables so evidence remains comparable.

**Keep `image_size=0` throughout H1**. The minimum-image G1 trial
already failed; adding the drain with the same image target isolates the new intervention.

Keep normal zram/disk priorities and the 90-minute hibernate delay.

H1 will begin in **Test**. Obtain sleep/resume evidence from this candidate so Fred can decide when to declare the 0.4.4 Run. The 20-success reliability trial can continue after that Run; it is not a prerequisite for getting 0.4.4 ready to Run.

## 1. Develop and prepare the candidate

1. Claim the implementation paths in the existing source and delivery checkouts. Recheck current heads, claims and installed assembly before selecting the new candidate. Retain e's exact delivery and native package identities as the Test rollback point.
2. Review the hook's action dispatch, concurrency, disk-swap capacity check, 60-second drain budget and restoration path. Resolve any defects needed for safe activation before freezing the candidate. In particular:
   - Plain suspend must leave zram enabled. The hibernate leg must drain only once; post-resume and failed-hibernate fallback must restore it.
   - Restore failures must remain visible and recoverable. The current script removes its saved state even when `swapon` fails; decide and implement an appropriate retry/recovery contract before Test.
   - Verify real timeout and interrupted-drain behavior, rather than relying only on the current test that checks timeout text.
   - Check disk space for both ordinary swapped pages and the hibernation image. The existing 80% drain guard alone is not proof that both fit.
3. Move the selected hook into
   `desktop/native/defaults/root/usr/lib/systemd/system-sleep/` under its `tam-hibernate-swap` name; update `origins.json`, executable mode and test references. Remove the deferred copy when the move is complete. Inspect the other installed sleep hooks for interaction or duplicate execution.
4. Run the focused hook and native-default checks. Extend behavioral coverage for the failure paths changed above. In `tamlinux-packages`, run the native staging/recipe checks and inspect the final native archive for exactly one executable drain hook, required dependencies and recorded hashes.
5. Prepare the exact product revision and matching assembly using the candidate preparation tools. Build the paired native and immutable user outputs, record component pins, archive/output digests and required check results, and inspect the transaction's complete changes. Use a short exclusive claim for checks/builds requiring a stable checkout.

**Deliverable:** A reviewable candidate sheet naming the letter, product and assembly commits, native archive/version/hash, immutable outputs, relevant checks, proposed install steps and concrete rollback procedure. A changed prepared assembly takes a new letter.

## 3. Establish physical sleep/resume proof

Arrange the timing with Fred, preserve open work and take one trial at a time. Prepare the existing display/GPU recovery procedure before sleeping.

| Trial | Required evidence |
| --- | --- |
| Short S3 suspend/resume | No zram drain; normal desktop, input and displays after wake. Does not count toward H1 hibernations. |
| Controlled direct hibernate/resume | Real hook invocation and drain duration, completed S4 image and restore, zram reenabled at its recorded priority, detector result and usable desktop. |
| Normal suspend-then-hibernate | Initial S3, natural RTC transition after the unchanged 90-minute delay, drain on the hibernate leg, successful S4 restore and restored zram. |

Use representative normal workloads and record zram load. An empty or tiny zram store does not establish drain performance under the workload that caused Fault G. Hook text claiming that data moved to disk is not a measurement of where every page went; correlate it with available swap/memory telemetry.

Do not add a separate awake `swapoff` experiment unless necessary. The actual hibernate trials measure the installed integration. If a separate diagnostic becomes necessary, propose its exact action and restoration steps and review with Fred before starting work on it.

After each wake, check application responsiveness, zram restoration, sleep logs and the Fault G detector. Capture any Fault F GPU event separately and use its established recovery procedure; a failed image followed by S3 is not a successful S4 restore. Do not use static checks to close these physical cases.

**Deliverable:** Evidence bound to the candidate for suspend, hibernate and resume. Update the sleep case and 0.4.4 checklist only to the extent proved; the remaining 0.4.4 gates and Run decision still follow their own process.

## 4. Continue H1 during normal use

For every hibernation attempt, retain an attempt ID; start and wake/abort times; candidate, kernel and boot identity; preflight memory/zram/tmpfs capture; hook drain amount/time or skip/stop reason; kernel preallocation and image result; verified S4 restore or fallback; detector result; restored swap state; and Fred's observed latency or sluggishness. Mark unavailable fields
explicitly. Export dated journal evidence before rotation, using retained kernel records across boots plus systemd-sleep, hook, preflight and detector records.

Maintain totals and a consecutive-success count in the canonical fault record. Count only verified real hibernations; identify controlled trials separately and state whether their workloads were representative. Keep G1's history closed. Segment the record when kernel, firmware, hook or swap policy changes materially so unlike configurations do not silently share a streak.

An ENOMEM/fallback resets the success streak and requires evidence review. A skipped or timed-out drain is recorded even if S4 succeeds; it cannot prove that the drain mitigates Fault G. Repeated 60-second timeouts, failure to restore zram, memory-pressure failures or unacceptable resume sluggishness stop progression until the cause and recovery are reviewed. Restore missing zram promptly through the prepared recovery steps; candidate rollback follows the recorded procedure and Fred's stage authorization.

**Fault retirement:** 20 consecutive verified H1 hibernations under
representative workloads, with no real detector failures and acceptable drain/resume behavior. Keep normal hibernation enabled and use event-driven evidence collection; add no periodic polling.
