## Key decisions and implementation notes

- The idle service and its model are vendored from the Omarchy 4.0.4 shell
  with the MIT notice, as the eleventh entry in `TAMLINUX_SERVICES` (`idle`).
  The Stay Awake switch, the two-stage idle cycle, the screensaver launch
  grace, the rule that only closing the screensaver ends a cycle once it is
  up, and the IPC target `idle` with its methods are unchanged; `ping` is
  added.
- **Every stage is off unless configured.** The timeouts come from
  `TAMLINUX_IDLE_SCREENSAVER` and `TAMLINUX_IDLE_LOCK` in seconds; unset or 0
  turns a stage off, and with both off the idle monitor is not armed, so an
  unconfigured service never starts the screensaver or the lock. (The source
  read 0 as at once and fell back to default timeouts.) Timeouts are capped where a QML timer interval would overflow. The model gains
  `cyclePlan()`, which works out the stages from the two timeouts.
- **Stay Awake is one file named by the environment**
  (`TAMLINUX_STAY_AWAKE_FILE`, default `~/.local/state/tamlinux/stay-awake`),
  so the host, the toggle command, and the idle suspend can share it. The
  service creates and removes it by argument, never as shell text.
- **Screensaver windows are counted from Wayland toplevels** (app id
  `org.tamlinux.screensaver`) in place of the compositor's window-event
  stream, so the service reads no compositor-specific events and stays inside
  the compositor contract's boundary.
- The stages run `tam-launch-screensaver`, `tam-system-lock`, and
  `tam-system-wake`. The original's locked-session check before the
  screensaver is left to the lock command, which ends the screensaver.
- The service has no surface of its own, so it does not import `Tam.Commons`.
