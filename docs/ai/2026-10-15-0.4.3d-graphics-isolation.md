# 0.4.3-d graphics environment isolation

- **CLI Tool**: Codex CLI (`codex`) `0.162.1`
- **Model**: `gpt-6.1-sol`
- **Transcript**: Retained privately by the author.
- **Prompt**:
  > I accept your recommendation. Build 0.4.3d and let's get that tested when you have it ready. In the meantime, we can keep running 0.4.3c with the fallback in place.

The accepted design supplies Quickshell with its paired Nix Mesa provider and
restores the caller's graphics environment before every inheriting QML launch.
The product changes start from the c Test source; later hibernation changes
remain outside this candidate.

All inheriting `Process` boundaries use `Util.hostEnvironment`; detached argv
launches use `Util.hostArgv`. Closed environments remain closed. Original empty
values remain distinct from absence, and internal provider markers are removed.
Only the two declared graphics keys can be restored: an arbitrary marker cannot
strip unrelated environment variables. Existing explicit process overrides survive.

Verification: 561 desktop tests pass, with one existing skip, in a valid checkout
with isolated fixture sockets enabled. The menu fixture now includes the Commons
module import; port comparison tests normalize only the new environment isolation.
The fontconfig fixture permits an already-installed Tamlinux rule on the test host.
Eight real offscreen Quickshell cases exercise direct and detached child environments,
including absent, empty, caller, mixed, stale and retained markers and an unwrapped
caller. This is process-environment proof, separate from desktop rendering.

The delivery wrapper independently created AMD hardware OpenGL contexts and
layer surfaces on three outputs without software overrides, including with
incompatible caller values. These were isolated one-pixel probes; they do not
constitute activation or full desktop acceptance.
