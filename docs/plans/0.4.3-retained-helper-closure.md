# 0.4.3 retained helpers, fresh defaults and explicit recovery

Develop work. Full testing readiness remains pending.

Imported 70 previously maintained desktop helper adaptations, retaining original
notices and hashes in `0.4.3-retained-helper-origins.json`. These include media,
window/layout/device controls, reminders, keybinding viewers, native package and
security menu chains, drive utilities, launcher management, crash notifications,
and the monitor watcher. Imported native/security operations still require their
root/settings recovery and physical proofs; syntax checks do not establish those.

The clean VM exposed empty first-login layout and missing embedded helper tools.
Startup now atomically publishes absent owned shell settings/layout, with all
eight plugins. Embedded shell scripts have immutable interpreters and declared
runtime dependencies. GUI launchers use UWSM service units. Canonical Helix
selection resolves native `hx`. The global workspace mode is named Tamlinux.

`tam-theme-init` generates absent baseline state without changing application or
root settings. `tam-session-init` creates only absent terminal, Helix, font,
terminal-selection and monitor override defaults, pairing custom XDG theme paths
and the Kitty socket. Existing bytes, modes and links remain intact. Monitor
menus, scaling, clamshell and the display panel use the same owned override path.
Package removal/AUR installation retain native transaction/build review rather
than suppressing confirmation. Invalid geometry, native identities and deadlines
stop before mutation. Launcher and monitor writers preserve prior files.

`tam-migrate-desktop` implements a finite, explicit first conversion batch:
desktop mode, bar identities, webapp executable names, six user Hyprland files,
Stay Awake and editor selection. Planning preserves originals and rejects
ambiguous links, unknown replacements and conflicting destinations. Complete
batch preflight precedes writes; prepared/writing/applied states support retry.
Explicit rollback restores prior destinations after archiving exact later bytes,
link identities and modes. Native/boot/GTK/device effects and the remaining
preserve-only inventory are outside this user-file batch. I06 remains pending.

The owned native integration recipe builds on independent Arch in the offline
VM. It registers the user session, supplies native asdcontrol and browser policy
adapters, root-owned Polkit actions, reload hooks and temporary-elevation boot
cleanup. Both actions require `auth_admin`, without cached authorization. Seven
installed endpoints have package ownership and exact hashes; unprivileged
requests fail. A root browser-policy fixture exercises apply, preservation of a
later root edit and explicit restore. Browser consumption, interactive PAM,
other root settings recovery, KMS and physical devices still require proof.
