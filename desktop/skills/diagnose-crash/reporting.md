# Reporting a crash

Identify the component from the executable, package owner, symbols and stack.
Application and compositor crashes may belong to their own upstream projects;
the desktop distribution's branding does not establish responsibility.

If this workstation supplies an upstream-engagement guide, read it before
preparing an external report. Repository-specific restrictions and the user's
posting instructions still apply. Preparing a report is separate from sending
it: do not open an issue, post a comment or upload a core without authorization.

Prepare a concise account of the exact package/version, timestamp, trigger,
reproduction, relevant stack and any local patches. Distinguish confirmed
facts from hypotheses. Remove private paths, document contents, tokens and
unrelated journal lines. Retain the original evidence locally. Never attach a
raw core dump; it contains process memory.
