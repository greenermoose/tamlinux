# 0.4.4 native login

Candidate c completes the login command naming change after the native a
session test. The native session entry invokes `/usr/bin/tam-session`, which
enters the installed `~/.local/bin/tam-hyprland-session` endpoint. The shell
package and Home Manager module deliver that endpoint from the same product
revision. Session data, units and environment variables retain their
`tamlinux` namespace. The previous command names are retired without aliases.

The native vendor package remains account independent. A consumer may select
`tamlinux.desktop` for normal automatic login, with its own username and
`Relogin=false` so logout exposes the greeter. A curated session directory
must update its Tamlinux entry's Exec in the same transaction. Remove an
obsolete duplicate registration explicitly; omitting it from an inventory
does not remove an installed file. Refresh SDDM's saved session selection
with the writer stopped, preserving its other state and file ownership.

Preparation requires the renamed native package, matching immutable user
generation, native desktop entry, and consumer policy to be available
together. Before Test, retain the previous native package and user generation,
then capture login configuration, registration and saved state from a verified
text console with SDDM stopped. Recovery saves later writes before restoring
the previous package, generation and login files. A generation alone cannot
undo root-owned login changes.

Source checks execute the native wrapper in a home with spaces, propagate the
user endpoint's status and refuse a stale endpoint. Package checks exercise
the native recipe and the generated Home Manager links. Physical automatic
login, logout/manual selection and recovery remain Test observations.

This login candidate retains the prior sleep hooks and boot providers. The
later boot handoff and sleep/resume need their own evidence before the 0.4.4
Run, with the old packages installed; package removal follows that Run, in 0.4.5.
