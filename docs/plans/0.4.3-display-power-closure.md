# 0.4.3 retained brightness, display and power chains

**Status:** Implemented and verified in Develop, 2026-10-12. This slice packages
28 retained helpers and their transitive display/lock/screensaver/suspend/wake
calls. It follows [network/power control closure](0.4.3-control-closure.md).
No source pin, version letter, installation or Test/Run/Release stage changed.

## Behavior and package owners

Focused-display brightness retains internal backlight selection, DDC/I2C external
displays, Apple HID controls, precise/nonuniform steps, repeat-event locking and
OSD. Redundant DPMS enable is skipped when all active outputs are already lit.
Failed backlight/keyboard/DDC writes and DPMS dispatches now return failure.
Keyboard off/restore, cycling and microphone-mute LED behavior remain available.
DDC ranges/unavailable results and Apple device selection use temporary caches.
Display adjustment requires a private session runtime directory for its lock.

Delivery declares brightnessctl, ddcutil, socat, coreutils, jq, awk, procps,
util-linux and systemd clients plus sibling helpers from the same output. Native
kernel backlight/LED, I2C/HID devices, udev permissions/ACLs and drivers remain
host owners. No client package grants native device access or installs host rules.
The packaged brightnessctl binary retains its own temporary save/restore state
under `/tmp/brightnessctl`; that state is not a settings-recovery snapshot.

Apple control validates brightness requests and selected character-device paths,
then calls fixed `/usr/bin/pkexec /usr/bin/asdcontrol`. It never selects a root
executable from caller PATH or invokes sudo. Native asdcontrol/Polkit and their
independent delivery/authorization still require proof. Tests substitute these
paths and HID predicates only in a disposable copy; no privileged execution ran.

Lock uses native hyprlock and the host's PAM stack. It refuses a missing PAM
stack before starting the locker or ending the screensaver. Existing XDG user
lock configuration wins; otherwise it uses the retained solid-background default
from `share/tamlinux/lock`. Layout reset, bounded optional 1Password locking and
screensaver cleanup are retained. Successful detached launch is not proof that
the compositor lock was acquired or that authentication works.

Sleep-lock requests locking before clamshell reconciliation, bounds process
queries and retries to logind's delay-inhibitor budget, and reports a missed
deadline. A running hyprlock process remains only an observation; startup can
precede compositor lock acquisition. The helper cannot prevent logind from
sleeping after the inhibitor expires. Real lock acquisition, authentication,
PrepareForSleep timing, inhibitor integration and failure recovery remain pending.
No service or inhibitor is enabled by command packaging.

Idle suspend now reads the same Stay Awake file as the shell and CLI. It retains
preflight memory/swap diagnostics and native `systemctl suspend-then-hibernate`.
Timeout, swap, RTC, hibernation support and delay remain host policy. Explicit
menu suspend remains independent of the idle-only Stay Awake check.

Screensaver launch/effect/toggle retains terminal selection, one window per
monitor, focus restoration, dismissal/cursor restoration and the manual `force`
interface. It ships terminal configurations and default text under
`share/tamlinux/screensaver`; per-file XDG user settings and Tamlinux branding
text take precedence. A missing ttfx returns failure before changing compositor
state. Native ttfx's independent package/source remains unproven. Actual terminal
mapping/fullscreen rules, effect rendering, font delivery and multi-monitor timing
need the packaged session and physical proof. Menu-only functions are retained.

Wake restores display/keyboard state and calls the complete clamshell/internal
monitor/mirror/toggle chain from the same output. Plain connector names are
validated before generated Lua; flag names reject path traversal. The monitor
reader uses XDG config roots and the Tamlinux scale knob. Live Lua/DPMS reload,
lid/DRM telemetry and display recovery still belong to the native compositor/host.

## Paired mutable state and recovery

| Interface | Reader/writer and state | Preservation boundary |
| --- | --- | --- |
| Stay Awake | Shell, `tam-toggle-idle` and `suspend-unless-stay-awake`: `$XDG_STATE_HOME/tamlinux/stay-awake`, HOME fallback, or valid absolute `TAMLINUX_STAY_AWAKE_FILE`. Invalid/empty overrides select the same fallback. | Earlier preserving writer remains shared. Legacy `indicators/stay-awake` needs offline migration classification; it is not consulted or deleted here. |
| Screensaver off | Generic toggle writer/reader and launcher: `$XDG_STATE_HOME/tamlinux/toggles/screensaver-off`. | Preserve bytes/link/absence before creating/removing; failure prevents mutation and notification. |
| Monitor flags and scale | Compositor helpers write/read `$XDG_STATE_HOME/tamlinux/toggles/hypr/{internal-monitor-disable.lua,internal-monitor-mirror.lua,internal-monitor-clamshell.lua,internal-monitor-scale}`. Selected config comes from `$XDG_CONFIG_HOME/hypr/monitors.lua`. | Preserve changed scale/flags before replacement/removal; unchanged observations avoid repeated snapshots. Native reload remains best effort. |
| Brightness state | Native devices, brightnessctl temporary save/restore files, runtime DDC/Apple caches and locks. | Volatile client/device state; no persistent configuration migration is performed. Real device recovery and cache invalidation require host proof. |
| Lock/screensaver settings | User XDG files override immutable defaults; branding reads `$XDG_CONFIG_HOME/tamlinux/branding/screensaver.txt`. | Helpers do not overwrite user configuration. Earlier branding, compositor scale variables, toggle sources and window/session rules require offline inventory and migration. |

The screensaver toggle can change its marker successfully before a notification
returns a bus error; callers must inspect the saved state when recovering.

Persistent snapshots use the existing mode-0700 settings-recovery helper and
completed manifests. Recovery is explicit: preserve present bytes and later user
writes first, review saved absence/link/content, then restore selected state only
when still owned by the attempted change. Reconcile native display state with
supported outputs and the reviewed configuration. A snapshot does not prove
restoration, ownership classification, or clean-host migration. No automatic
restore or pruning runs here. Prior DNS/GTK/power recovery limits still apply.

and 21 audit regressions. Six targeted cases reject original helpers for failed
brightness/DPMS/keyboard writes, the stale Stay Awake path and missing toggle/
