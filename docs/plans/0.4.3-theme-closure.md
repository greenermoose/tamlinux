# 0.4.3 owned theme, font, assets and branding

Develop implementation, 2026-10-13. Theme switching no longer delegates to an
inherited engine. Theme/background/font pickers and writers, generation,
application tint/reload adapters, font installation and About/screensaver branding
have maintained product source and declared delivery tools. No candidate, pin,
installed configuration or lifecycle stage changes.

## Delivered behavior

The package carries 22 retained palettes/background sets and the supported
application templates. Source notices and input-byte hashes are in
`desktop/assets/origins.json`; copied code/assets retain MIT attribution.
Retired Hermes templates are excluded. The prior branded wallpaper is excluded;
other retained backgrounds, previews and unlock images retain their bytes.
Unlock images are data here: boot/Plymouth ownership and acceptance remain pending.

`tam-theme-set` generates and validates a new theme before publishing it. All
pickers, shell readers, terminal templates and writers use owned XDG paths:
`$XDG_STATE_HOME/tamlinux/current/{theme,theme.name,background}` and
`$XDG_CONFIG_HOME/tamlinux/{themes,themed,backgrounds,branding}`. The background
service's fallback now matches the delivery module and writer. Generation uses
immutable package templates, followed by the user's templates and theme-specific
files. Repo-installed themes cannot supply Lua, terminal launch configuration,
VS Code extension descriptors or external symlinks. Valid legacy Alacritty
palettes can still be converted to `colors.toml`.

Published theme generations use an atomic selection link. Private journals save
original bytes, directories and link identities before file mutation; a failed
apply restores the previous file selection/application files. Old generations
and journals remain available for recovery. This is file-level failure recovery,
not the final interrupted migration or native/service rollback collector.

Background selection, cycling, installing into the current user folder and
refresh share one link. Refresh preserves the selected background. Image picker
previews remain available after preload, and picker waits have a deadline. Theme
install accepts explicit independent HTTPS/SSH repositories, rejects transport
helpers and inherited endpoints, and refuses to overwrite an existing theme.
Removing an extra theme preserves it first and returns an active selection to a
bundled baseline.

The font build renames the inherited font to **Tamlinux Icons**. Build assertions
compare `cmap`, glyph outlines and metrics; all seven menu consumers use the owned
family. The old font identity is never installed. Original mark origins and
licenses remain attributed. Locked Nerd Fonts JetBrains Mono supplies the
retained monospace baseline. Home Manager enables fontconfig discovery of the
command package. Font selection preserves terminal/fontconfig originals, handles
inline Alacritty families and each consumer's escaping, and appends the owned
Fontconfig rule after existing user settings. Malformed XML restores earlier
writes. Selecting fonts does not replace unrelated preferences.

About retains terminal fitting, remembered dimensions and custom fastfetch
configuration support; its default config displays the exact packaged Tamlinux
version and reads the owned logo. Branding text/image/reset calls the owned
editor/file picker/converter and preserves prior files. Packaged ImageMagick and
UTF-8 gawk provide offline PNG/SVG conversion with validated dimensions and
atomic output. Default About/screensaver text identifies Tamlinux.

Application adapters cover Foot/tmux, GTK, Pi, Claude, T3 Code, VS Code/Codium/
Cursor, Obsidian and supported keyboard tinting. The generated VS Code color
extension is local and owned; switching does not fetch arbitrary extensions.
Direct file-writing application setters preserve the same finite application
paths before mutation. Retained terminal defaults are product data; effective
consumer includes, application theme selectors and fresh-session endpoints still
need migration/session wiring. This slice does not rewrite live consumer files.

The font installer retains native Arch transactions. Owned package clients inspect
the dependency-inclusive transaction, refuse failed resolution and inherited
repositories/packages, and invoke the native Pacman trust endpoint through
Polkit. Font installation is exercised with recorded boundaries; no native
package is installed during development checks.

## Native and acceptance boundaries

Browser tint has an owned client and fixed-path root adapter source at
`desktop/native/theme-browser-policy`. A selected independent native provider
must install `/usr/bin/tam-theme-set-browser-policy`, hardened policy directories
and its authorization/recovery policy. With installed browsers but no adapter,
application reports failure and the theme's saved files are restored. This source
is not installed into `/usr/bin` by the user command package. GTK/dconf, browser
policy, keyboard device changes and external process state need native/runtime
rollback evidence; file journals alone do not restore those effects.

Native font packages, Polkit/Pacman, browser policy, application providers,
compositor Lua, actual QML/font loading, editor/session includes and retained
visual behavior need the complete independent assembly and clean graphical proof.
Plain offline generation cannot substitute for those workflows. Actual install,
re-login, theme/font/background switches and return to baseline remain I04/I07
acceptance cases. Neither this implementation nor an audit count closes I01–I09.
