# 0.4.3 packaged capture chain

Develop implementation, 2026-10-13. Screenshot, region selection, screen
recording, webcam selection/placement, OCR and QR decoding now live in nine
product command directories, including the owned screenshot annotation adapter.
No source pin, candidate letter, installation or stage transition is changed.

## Retained behavior and ownership

The menu and bar use `tam-capture-screenrecording --status` (exit 0 when recording,
1 otherwise). It checks the PID and Linux start tick of the launched backend;
Nix store argv paths and stale/reused PIDs cannot confuse status or stop. Stop
signals only that recorded process. A private runtime lock serializes start/stop,
startup and graceful stop wait at most five seconds each, and a failed backend
returns failure after child/state/partial-output cleanup. Stop remains available
if the configured Videos directory was changed or removed. Repeated invocation
still stops an active recording. Audio tracks, optional portal/fullscreen flow,
webcam placement (with failed mapping preventing recorder startup), first-frame trimming and normalization retain their interfaces.

Screenshot modes/processing are validated, saved names are unique, cursor state
is restored, and cancellation releases the freeze. Copy captures into a temporary
file before touching the clipboard; capture/decoder/clipboard failure cannot
claim success. OCR preserves literal text and its selected language. QR enables
only QR symbology, copies with `--sensitive`, and never prints decoded secrets or
puts them in notifications. A notification outage does not undo completed work.

`tam-capture-edit <image>` preserves the Tensaku annotation flags and literal
filename argv. `TAMLINUX_SCREENSHOT_EDITOR` / `--editor=` retain their override
interface; the default now uses this owned adapter rather than an inherited
wrapper. Native Tensaku still needs an independently selected provider.

Delivery declares the exact locked nixpkgs grim, slurp, hyprpicker, wl-clipboard,
GPU Screen Recorder, mpv, FFmpeg/ffprobe, V4L2 clients, zbar, Tesseract and English
language data. `share/tamlinux/capture-tools.json` records immutable tool/data
paths. Additional OCR languages require a selected language-data provider.
Packaging clients does not enable native DRM/camera/audio access, configure a
portal, provide the graphics-driver bridge or grant KMS helper privileges.

## State and recovery boundary

The recorder, region picker and webcam position reader use
`${XDG_RUNTIME_DIR:-${XDG_CACHE_HOME:-$HOME/.cache}}/tamlinux-capture`, mode 0700.
The recorder PID/start tick, webcam PID/start tick, output filename, region, lock
and optional debug log are volatile session state. Region hotkeys share the same
marker directory. No generic `/tmp` recording filename/log remains.

Pictures/Videos locations retain `TAMLINUX_SCREENSHOT_DIR` and
`TAMLINUX_SCREENRECORD_DIR`, with XDG user-directory configuration read from
`XDG_CONFIG_HOME`. Saved user images/videos remain user data. There is no
persistent settings migration or live consumer cleanup in this slice. Stop old
recordings before switching candidates; preserve user files and earlier runtime
observations in the reviewed recovery kit. A new candidate must never signal an
unrecorded process to adopt an earlier recording.

The inherited logical geometry is retained. Negative positions, fractional
scale/transform disagreements and picker/overlay policy still require the
[bounded original-workflow evidence](non-theme-compatibility.md#retained-capture-evidence).
This slice changes process ownership/failure handling, not geometry formulas.

## Validation and remaining proof

21 capture regressions pass against recorded IPC/capture/decoder tools and real
Linux child lifecycle. The bar's exact port comparison now accounts for owned
status. Two stale audio port assertions from the prior slice were corrected to
check the paired owned tuning name. Nix build and installed integration pass with 61 isolated probes, including
actual packaged OCR/English data and QR decoding. Four methods reject the import
baseline through six failed assertions (no runner errors). 429 desktop checks
pass with two existing skips and all 50 delivery audit/gate/collector tests pass.

[Exact immutable-output evidence](https://github.com/greenermoose/tamlinux-packages/blob/develop/docs/evidence/0.4.3-capture-closure.json)
records the source/recipe snapshots, all five outputs, installed integration,
full probes and inventory: 382 runtime files, 61 unresolved lexical names and
51 inherited locations. Readiness is false. The initial offline builds hit a
deleted upstream jbigkit patch URL; fetching unchanged locked binary outputs from
the official Nix cache allowed the final offline pass. Documentation follows the
inspected source snapshots; no candidate was selected.

Required native provider/policy selection, clean graphical capture/clipboard,
portal and KMS recording/audio/webcam, mixed-display transforms and physical
failure/recovery proof remain pending. Mocked successful workflows do not close
I01–I09 or authorize Test. The next product task is theme/background/fonts/assets/
branding ownership, followed by session/native integration and executable
