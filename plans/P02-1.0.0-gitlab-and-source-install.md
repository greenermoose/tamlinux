# P02 · Tamlinux 1.0.0 on GitLab

- **Phase:** PH04
- **Status:** Planned for 1.0.0, after Northern Torch.

Tamlinux 1.0.0 starts four GitLab repositories with fresh Git histories. Each starts with a lean source tree so fresh clones stay small and fast. Keep build inputs, useful tests, and required license and attribution notices in the source trees.

## Repository ownership

| Repository | What belongs there |
| --- | --- |
| `tamlinux` | The core system, `tam-bud` (renamed from `tam-nut`), and the basic installation instructions. |
| `tam-tooee` | Programs that can run directly on the Linux kernel console, including `tam-clam`, `tam-edit`, and `tam-data`. They also work in graphical terminal emulators. |
| `tam-gooee` | Programs and widgets that need a graphical session, including `tam-last` and the system-bar widgets. `tam-last` opens a Wayland window. |
| `tam-docs` | Companion documentation such as man pages, tldr pages, Info manuals, and rootstock references. |

## Installation

Start on a supported rootstock, the base Linux distribution on which Tamlinux runs. Clone `tamlinux` from GitLab, run `make` to build it, then run `make install`. `tam-bud` bootstraps the rest of Tamlinux from Git clones. A console-only install can skip cloning `tam-gooee`. The basic instructions are available in `tamlinux`, with `tam-docs` available separately.

## Milestones and acceptance

1. **Prepare the four repositories.** Check each source tree for the
   required build inputs, licenses, tests, and an installation entry point
   where applicable. Measure clone sizes and checkout times.
2. **Prove the bootstrap on fresh Arch.** Start with a supported bare
   rootstock and run the documented `tam-bud` and Make installation path
   from fresh GitLab clones. Prove console-only installation without
   `tam-gooee`, including `tam-clam`, `tam-edit`, and `tam-data` on a real
   console. Exercise `tam-last` with them in the graphical profile and
   verify recovery.
3. **Complete cutover.** Add the repository map and tested rootstock
   instructions to the README. List a rootstock only once it passes the
   fresh-install path. The 1.0 release is the baseline for PH05.
